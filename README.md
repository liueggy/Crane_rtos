# Crane_rtos

基于 STM32F103ZET6、FreeRTOS、CubeMX 和 CMake 的起重式散料货物搬运机器人控制工程。

项目面向物流技术创意赛运输豆子任务，目标是让机器人完成自主识别、取料、绕障运输、准确放料和归位。当前工程已经完成硬件控制框架和分模块调试基础，完整视觉搬运流程仍需结合实机继续开发。

## 1. 项目状态

- 四路 L298N 直流电机双 PWM 驱动结构；四轮方向、编码器测速和闭环同步控速已完成实机验证。
- 两路舵机 PWM；PA0 旋转舵机和 PA1 夹爪舵机均已完成关键角度实机标定。
- K230 USART2 DMA 收发框架已保留，当前运行时收发关闭。
- OLED 五页全中文状态界面。
- 急停、四路对射光电限位和 EXTI 事件框架。
- FreeRTOS 任务框架、独立红外任务、路线表和比赛状态机骨架。

### 2026-07-17 舵机与红外调试进度

- PA0 / TIM2_CH1 为 270 度旋转舵机；规定 0 度对应舵机实际 6 度，后续规定角度统一叠加 6 度安装偏移。
- PA1 / TIM2_CH2 为 180 度夹爪舵机；实机确认 `10°` 完全闭合、`45°` 可完全放下豆子、`100°` 是能伸入放置盒的最大张角。

- 该阶段的夹爪红外演示绑定已经解除，当前红外按键改用于 X/Z 步进轴手动调试，映射见“红外遥控”章节。

### 2026-07-19 双步进轴红外调试进度

- X/Z 两轴均使用 TB6600 的 4 细分，即 `800` 脉冲/圈；TIM1 当前为 `PSC=71`、`ARR=399`，脉冲频率约 `2.5kHz`。
- 运行时 CCR 为 `250`；TB6600 按脉冲边沿计步，占空比不决定转速。按 800 脉冲/圈计算，理论电机转速约 `187.5RPM`。实机确认当前两轴速度合适，暂不提高频率或修改细分。
- 遥控器数字 `1/2` 分别选择 X/Z 轴；`LEFT/RIGHT` 设置 X 轴反/正转，`UP/DOWN` 设置 Z 轴正/反转，`POWER` 启停当前轴。
- 手动调试采用单轴互锁：切换控制轴时先停止原轴，防止两轴意外同时运行。
- 运行中反向时先停止并缓存目标方向，等待 `300ms` 后再恢复；等待期间按 `POWER` 会取消换向并保持停止。
- 急停或任一限位故障存在时，两轴停止且红外命令不能重新启动电机。
- OLED 步进页面已完成中文显示：遥控步进、选择轴、运行状态、方向状态和换向等待。
- 每个通过 NEC 校验的遥控按键都会触发 PB8 蜂鸣器短响约 60ms；采用非阻塞定时关闭，不影响红外解码和换向状态机。安全故障下蜂鸣仍表示按键码已收到，但不会执行电机动作。

### 2026-07-23 全机构遥控与 OLED 调试界面

- 遥控器采用“当前页面决定控制对象”：`VOL-/VOL+` 或 K0/K1 翻页；步进页内 `2/3` 选择 X/Z，舵机页内 `4/5` 选择旋转/夹爪，底盘页内 `6/7/8` 调整底盘。
- 四个直流电机不再支持单轮遥控，底盘始终四轮整体启停和整体换向。
- `VOL- / VOL+` 切换 OLED 上一页/下一页；开机进入总览页。
- `0` 为软件总停止，关闭四轮底盘和 X/Z 步进轴；舵机保持当前位置。
- 切换控制对象时先停止此前选中的底盘或步进轴，避免运动机构在后台继续运行。

## 4. 克隆后首次构建

在仓库根目录执行：

```powershell
git clone <仓库地址>
cd Crane_rtos
cmake --preset Debug
cmake --build --preset Debug
```

或者使用已经生成的构建目录：

```powershell
cmake --build build\Debug
```

成功后主要产物为：

```text
build/Debug/Crane_rtos.elf
```

Release 构建：

```powershell
cmake --preset Release
cmake --build --preset Release
```

如果首次构建报 `arm-none-eabi-gcc is not recognized`，这是本机工具链 PATH 问题，不是项目源码问题。若报 `ninja is not recognized`，安装 Ninja 并加入 PATH，或在 CMake 中改用本机可用的生成器。

## 5. CubeMX 配置与重新生成

CubeMX 工程文件为：

```text
Crane_rtos.ioc
```

打开后修改引脚、定时器、DMA、FreeRTOS 或 NVIC 配置，再点击 **Generate Code**。生成完成后必须重新构建：

```powershell
cmake --build --preset Debug
```

生成后至少检查：

- `Core/Inc/main.h` 的标签与预期一致。
- `Core/Src/main.c` 中 `MX_TIM8_Init()` 存在。
- TIM3/TIM8 四通道 PWM 存在。
- USART2 DMA RX/TX 和空闲线接收存在。
- `PC5 / LIMIT_Z_MIN` 为 `GPIO_MODE_IT_RISING + GPIO_PULLDOWN`。
- `PE0/PE1/PE2` 同样为高有效限位输入。
- `EXTI9_5_IRQHandler` 同时转发 `LIMIT_Z_MIN_Pin` 和 `ESTOP_IN_Pin`。

CubeMX 可能重写生成区域，因此手写业务应放在 `USER CODE` 区域或独立 `.c/.h` 文件。修改 `.ioc` 后不要只修改生成的 `main.c`，否则下次生成可能丢失配置。

项目当前没有把 STM32CubeProgrammer 或 ST-LINK 的绝对路径写入 CMake，也没有固定烧录脚本。不同电脑只需要在本机安装工具并替换命令路径。

| SWDIO | PA13 |
| SWCLK | PA14 |
| GND | GND |

烧录前确认：目标板供电正常、ST-LINK 电压与目标板一致、所有电机驱动器处于安全停止状态。

## 7. 硬件基线

### 直流电机与编码器

四路直流电机由集成两颗 L298N 的四路驱动板控制。电机使用 12V，编码器统一使用 STM32 的 3.3V。接线或改线前必须同时关闭 12V 电机电源和控制板电源。

#### 电源与共地

```text
12V电源正极  -> L298N VCC / 电机电源+
12V电源负极  -> L298N GND
STM32 GND     -> L298N GND
编码器黑线    -> STM32 GND
```

12V 电源负极、L298N GND、STM32 GND 和四个编码器黑线必须共地。模块自带的 5V 输出暂不连接 STM32，避免与控制板自身电源互相倒灌。编码器蓝线严禁接入 12V。

#### 电机输出与控制输入

| 电机 | STM32 PWM 1 | L298N输入 | STM32 PWM 2 | L298N输入 | 电机红/白线 |
| --- | --- | --- | --- | --- | --- |
| M1 | PA6 / TIM3_CH1 | IN1 | PA7 / TIM3_CH2 | IN2 | OUT1 / OUT2 |
| M2 | PB0 / TIM3_CH3 | IN3 | PB1 / TIM3_CH4 | IN4 | OUT3 / OUT4 |
| M3 | PC6 / TIM8_CH1 | IN5 | PC7 / TIM8_CH2 | IN6 | OUT5 / OUT6 |
| M4 | PC8 / TIM8_CH3 | IN7 | PC9 / TIM8_CH4 | IN8 | OUT7 / OUT8 |

L298N 的 EN1 至 EN4 只保持使能，不承担 PWM。如果驱动板带 EN 跳帽，调试时保留跳帽；如果是独立 EN 输入，则按照模块说明置于有效电平。当前软件采用双 PWM 控制：

```text
正转：IN1=PWM，IN2=0
反转：IN1=0，IN2=PWM
停止：IN1=0，IN2=0
```

TIM3 控制 M1/M2，TIM8 控制 M3/M4，两者当前均为约 10kHz PWM。STM32 的 3.3V 高电平满足该模块标注的 2.3V 以上有效输入要求。

#### 编码器接线

每个电机的六根线定义：

```text
红线 -> 电机端，接对应 OUT 奇数端
白线 -> 电机端，接对应 OUT 偶数端
蓝线 -> STM32 3.3V
黑线 -> STM32 GND
黄线 -> 编码器 A 相
绿线 -> 编码器 B 相
```

| 电机 | 黄线 A | 绿线 B | 蓝线 | 黑线 |
| --- | --- | --- | --- | --- |
| M1 | PD10 | PD4 | 3.3V | GND |
| M2 | PD13 | PD5 | 3.3V | GND |
| M3 | PD14 | PD6 | 3.3V | GND |
| M4 | PD15 | PD7 | 3.3V | GND |

编码器 A 相使用上升沿 EXTI，B 相作为方向判定输入，两者均启用内部上拉。驱动轮实测周长为`263.9mm`，统一保存在`AppConfig.wheel_circumference_mm`。2026-07-28底盘直线复标将输出轴计数修正为`468计数/圈`，对应理论分辨率约`263.9/468=0.5639mm/计数`。复测结果如下：

- `1000mm / 40RPM`：M1=`900mm`、M2=`1055mm`、M3=`1078mm`、M4=`1004mm`，四轮平均约`1009mm`。
- `2000mm / 40RPM`：M1=`1848mm`、M2=`1995mm`、M3=`2132mm`、M4=`2042mm`，四轮平均约`2004mm`。
- `110RPM`下实测`1000mm`和`2000mm`的总位移均可控制在目标上下约`100mm`内，包含惯性停车距离。

因此当前统一里程比例暂定为`468计数/圈`。M1计数持续偏低、M3持续偏高，后续应结合底盘终点横向偏移和航向角判断是单轮编码器比例差、轮径差还是打滑；在证据明确前不要仅按四轮计数差直接修改PI。正式分段路线不使用编码器里程决定停车，编码器只负责闭环同步和宽松行程校验；所有Y地标均以两侧光电门独立触发为界。

#### 电流、散热与首次上电

驱动板标注的 2A 通常指单路电机桥的短时峰值，不是四路模块总共只有 2A，也不代表四路可以长期各输出 2A。建议将单路连续电流控制在约 0.8～1.2A 范围内，具体上限取决于散热片、风冷和 PCB 走线。四路总电流还受 12V 电源额定电流限制。

首次上电按以下顺序进行：

1. 将车架架空，确保四个轮子均不接触地面。
2. 断电状态下检查 12V 与 3.3V 之间不存在短路。
3. 只连接 M1，电源设为 12V、约 1A 限流，验证正反转和编码器计数。
4. 依次接入 M2、M3、M4，每增加一路都检查空载电流和 L298N 温升。
5. 四路空载正常后再逐步提高总限流，12V/5A 电源最大只能提供约 5A 总电流。
6. 确认急停、停止命令和软件 PWM 均有效后，再让轮子落地低速测试。

如果某个轮子的正转方向与整车定义相反，优先调整 `motor_polarity[]`，也可以断电后交换该电机红白线。编码器方向错误时再交换黄绿线或调整编码器极性，避免一次同时改变电机线和编码器线而难以定位问题。

当前实机规定正方向已经标定：M1、M2 的安装方向与 M3、M4 相反，因此固定使用 `motor_polarity = {-1, -1, 1, 1}`。上层底盘和路线代码只使用统一的正负速度定义，不应再次针对 M1/M2 单独交换方向。

2026-07-23 串口闭环遥测确认：开环规定正向下 M1/M2 原始编码器计数为负，因此反馈配置固定为 `encoder_polarity = {-1, -1, 1, 1}`。同时实机的 M3/M4 驱动线序与最初逻辑标号交叉，软件已交换 TIM8_CH1/2 与 TIM8_CH3/4 的逻辑映射，使 P3 对应编码器3、P4对应编码器4。该修正不改变四轮已经验证正确的开环物理正方向。

### 世界坐标约定（2026-07-27确认）

- 世界XY原点位于场地图示右上角。
- `+X`沿场地横向向左；X轴步进电机正转时夹爪沿`+X`移动。
- `+Y`沿场地纵向由豆子区指向数字区；底盘规定正转时沿`+Y`移动。
- `+Z`竖直向下；Z轴步进电机正转时夹爪下降。
- X轴右端定义为`X=0`，左端约为`X=33924`脉冲。
- Z轴最高安全位置定义为`Z=0`，触底光电门位置约为`Z=5784`脉冲；触底点是Z最大值，不能再定义为零点。
- 软件中步进轴`reverse=0`表示沿坐标正方向运动，`reverse=1`表示沿坐标负方向运动；带符号脉冲累计遵循同一规则。
- 底盘四轮的安装和编码器极性已在驱动层归一化，上层路线使用正速度表示`+Y`，负速度表示`-Y`。
- 世界坐标、机构坐标和摄像头像素坐标必须分开保存，K230画面横坐标不能直接作为龙门X轴坐标使用。

Z轴回零时可先向下低速寻找触底光电门，将该点标记为`Z=5784`，随后向上运行已标定行程到达`Z=0`。在尚未完成二次回零验证前，只能将该坐标视为脉冲估算值，光电硬限位仍具有最高优先级。

### 世界地图与自动任务框架

世界地图采用固定场地的“度量坐标+离散Y地标”模型。实物现已安装完成9组光电定位挡板，从豆子区沿`+Y`到数字区依次排列；左右底盘各有一个光电门，每组地标两侧各一片挡板。单侧触发只锁存本组事件，只有两侧均触发才算整车完成该地标确认；目标点随后让四轮同时停车。A/C夹取挡板同时是豆子端机械允许的最上极限，2/3/4号箱挡板同时是数字端最终定位，地图不再额外定义不存在的顶端或底端边界挡板。

路线分为两类：

- 识别阶段：起点到数字识别点、数字识别点到豆子识别点使用`DIRECT_SURVEY`路线，允许沿标定侧直行，不要求在障碍之间交叉换边。
- 正式搬运阶段：豆子区与数字区往返使用`REQUIRE_CENTER_PASS`路线，拓扑中必须包含`WORLD_STATION_START`；缺少中心节点时路线执行器拒绝启动。

当前联调阶段所有自动路线统一使用`50 RPM`，暂不区分巡航段与靠站段；各段光电定位验证稳定后，再逐段恢复中间快速、终点低速的速度规划。路线段仍需逐段填写实测距离、方向和超时；数组中的推荐速度不会让未标定路线自动生效。左右光电门独立锁存同组事件但不单边停车，两侧都遮挡后才在目标点同时停止四轮。单侧锁存超过0.6秒或路线超时会进入路线故障。

正式搬运路线到达起点Y地标后会先停止底盘，并在Z不低于离地75mm安全高度的条件下执行一次X向换边：当前位于右半场时移动到左侧四分之三行程位置，当前位于左半场或中点时移动到右侧四分之一行程位置，完成后才继续下一段Y运动。因此即使抓取箱和目标数字箱位于同侧，货物路径仍会在两个障碍物之间经过起点并实际交叉换边。识别阶段使用`DIRECT_SURVEY`路线，不强制执行这次X换边。

自动启动采用“先清限位、再快速建立绝对坐标”的顺序。比赛摆放时软件将X初始化为中点`16962`、Z初始化为触底`5784`；按已标定的281mm全行程换算，夹爪先向上约`1544`脉冲，到达离地约75mm、绝对`Z≈4240`并离开PB11。由于X/Z共用PB11且驱动层强制互斥，不能同时抬升和横移。随后X向右端连续运行，触发PB11后建立`X=0`，再沿`+X`移动`8500`脉冲对准物理2号箱；此时已经允许底盘开始识别路线，不再继续升到机械最高点。任何一步未触发预期光电门或脉冲运动异常都会进入故障状态。

识别任务完成并建立搬运表后，控制器立即将夹爪舵机张开到`100°`，同时把Z从识别高度抬到抓取预备高度`Z=2300`。该位置比三档抓取中最高的`Z=2500`再高200脉冲，约9.7mm，便于后续横移到目标豆子箱后再下降抓取，同时避免每次都升到`Z=0`浪费时间。`200`脉冲预留量集中定义为`BEAN_PICKUP_PREP_MARGIN_PULSES`，后续按实机空间调整。

比赛起点上电时Z触底会遮挡这一个共用光电门，此时X轴必须位于不遮挡的位置。自动启动只在已知起点状态下调用`StepperAxis_ArmPhotoLimitEscape(STEPPER_AXIS_Z, 0)`，将“向下”记录为触发方向，只允许Z轴反转向上脱离；继续向下和X轴启动仍被互锁禁止。确认光束恢复后，才执行后续X轴正向偏移动作。

所有未知参数默认保持未标定，不能用0代替。调用`RobotController_RequestStart()`后，状态机先检查：

- 各挡板站点的世界Y坐标；
- 8个箱位的X脉冲和抓放Z脉冲；
- A/B/C的X、Z、旋转角、俯仰脉宽和稳定时间；
- 两条识别路线、两条强制中心搬运路线及结束路线的每一段距离、转角、速度和超时。

任一参数缺失时进入`ROBOT_STATE_CALIBRATION_REQUIRED`，不会启动步进或底盘。可通过`RobotController_GetMissingCalibrationMask()`查看缺失类别。后续建议按“站点Y坐标 -> 识别姿态 -> 箱位X/Z -> 直行识别路线 -> 中心搬运路线 -> 完整抓放”的顺序逐项写入标定值。

### 舵机、OLED、K230

- 旋转舵机：PA0 / TIM2_CH1，物理范围 0～270 度，对应 500～2500μs；规定角度自动增加 6 度安装偏移，上电和遥控复位显示为规定 0 度，实际输出 6 度。
- 夹爪舵机：PA1 / TIM2_CH2，范围 0～180 度，对应 1000～2000μs；闭合/放豆/最大张角分别为 10/45/100 度，上电和遥控复位到闭合的 10 度。
- 两路舵机遥控 UP/DOWN 每次增减 10 度。旋转规定角限制为 0～264 度，夹爪工作角限制为 10～100 度，超过边界的命令自动夹紧。两路均为 50Hz，并使用独立 5V/6V 电源。
- OLED：PB6/PB7 / I2C1，SSD1306，常用地址 0x3C。
- K230 预留：PA2 为 USART2_TX，PA3 为 USART2_RX，115200 8N1，DMA RX/TX。当前 `K230_LINK_RUNTIME_ENABLED=0U`，不启动 DMA 接收也不发送信息；接入 K230 后改为 `1U`。

### 按键、急停、对射光电

- K0：PE4，低有效下降沿；K1：PE3，低有效下降沿；急停：PE7，低有效下降沿。
- K0/K1 当前只切换 OLED 上一页/下一页，不直接驱动执行机构；当前运动调试统一通过红外遥控完成。
- X 最小/最大：PE0/PE1；Z 上/下：PE2/PC5。
- 光电模块无遮挡 `DO=低`、遮挡 `DO=高`，四路限位使用内部下拉和上升沿 EXTI。
- 光电模块只有在 DO 高电平不超过 3.3V 时才能直接连接 STM32；高于 3.3V 必须做电平转换。

### 红外遥控

- 接收端 DO：PB9 / TIM4_CH4，标签 `IR_REMOTE_RX`；应连接 3.3V 逻辑电平的解调型红外接收模块，且必须与 STM32 共地。
- TIM4：CH4 在 CubeMX 中配置为上升沿输入捕获、`PSC=71`、`ARR=65535`，计数分辨率为 1 us；软件在每次捕获后交替切换边沿以完成 NEC 解码。必须启用 `TIM4_IRQn`，不要将其再用作 HAL 时基。

| 按键 | NEC 命令码 | 当前功能 |
| --- | ---: | --- |
| 1 | `0x16` | 当前保留，不跨页面切换机构 |
| 2 | `0x19` | 仅在步进页选择 X 轴 |
| 3 | `0x0D` | 仅在步进页选择 Z 轴 |
| 4 | `0x0C` | 仅在舵机页选择旋转舵机（PA0） |
| 5 | `0x18` | 仅在舵机页选择夹爪舵机（PA1） |
| 6 | `0x5E` | 仅在底盘页且停止时切换开环/四轮闭环 |
| 7 / 8 | `0x08` / `0x1C` | 仅在底盘页将闭环目标转速减/增 10 RPM |
| UP | `0x46` | 底盘/步进设正向，舵机增加 10 度 |
| DOWN | `0x15` | 底盘/步进设反向，舵机减少 10 度 |
| POWER | `0x45` | 底盘/步进启停；旋转舵机回规定0度，夹爪回闭合10度 |
| 0 | `0x42` | 软件总停止：底盘和双步进轴停止 |
| VOL- | `0x07` | OLED 上一页 |
| VOL+ | `0x09` | OLED 下一页 |

UP、DOWN和POWER只作用于当前OLED页面；总览页和系统页不响应机构动作。离开底盘或步进页面时先停止原机构，防止后台继续运动。底盘遥控占空比固定为 `75/99`。底盘和步进电机只有在停止状态下才能改变方向；步进运行中收到反向命令时仍采用300ms停机死区。急停和限位故障优先级最高，故障状态仅允许OLED翻页，不执行运动命令。

底盘默认处于 `CLOSED` 闭环模式，默认目标速度为 `110 RPM`，但上电保持停止，收到明确启动命令后才运动。按 `6` 可在底盘停止时切换开环/闭环，按 `7/8` 调整目标转速。闭环模式使用四轮独立 PI、速度前馈和平均速度同步补偿；开环模式仅用于检查驱动、编码器计数和物理方向。

四轮测速仍以 10ms 周期执行控制，但将编码器增量累计 50ms 后再计算 RPM，降低低脉冲数造成的显示跳变。闭环停止命令会立即将四路 PWM 清零；同向速度控制禁止跨零输出反向制动力，避免某轮超调时突然反转。现阶段不加入 D 项，因为编码器量化噪声会被微分项显著放大。

2026-07-23 实机在线调参结果：`KP=0.8`、`KI=2.5`、`FF=0.65`、`SYNC=0.2` 保持不变，测速滤波系数由 `0.35` 优化为 `0.25`。在架空空载测试中，40/60/80/100/120 RPM 均可稳定跟踪；40 RPM 时四轮平均瞬时离散度约 `0.88 RPM`，120 RPM 时约 `2.03 RPM`。这些参数是空载基线，底盘落地承载后仍需重新验证直线偏移和抗扰性能。

以下 USART2 遥测和在线调参协议代码仍保留，但当前运行时开关关闭，不会接收命令或输出 CSV。后续接入 K230 或继续串口调参时，先将 `K230_LINK_RUNTIME_ENABLED` 改为 `1U`。

启用后，USART2 可按 115200 8N1 输出 CSV：

```text
CSV:M,tick,closed,run,dir,target,r1,r2,r3,r4,p1,p2,p3,p4,c1,c2,c3,c4
M,12340,1,1,0,40,39,41,38,40,52,49,55,51,1024,1010,998,1018
```

`r1~r4` 为滤波后的整数 RPM，`p1~p4` 为控制器实际输出命令，`c1~c4` 为累计编码器计数。遥测由低优先级 UART 任务以约 20 Hz 格式化，并使用非阻塞 DMA 投递；串口忙时丢弃本帧，不占用 10ms 高优先级电机控制任务。

### 底盘距离标定页

“距离标定”页用于验证车轮周长和编码器每圈计数。默认目标为`500mm / 40RPM`，底盘采用四轮闭环同步控制；启动时记录四路编码器累计计数，以四轮绝对增量平均值达到理论目标计数时自动停车。页面中的“计”表示由编码器参数换算出的距离，“差”表示四轮中最大与最小里程之差，二者均显示为整数毫米，内部计算仍保留0.1mm精度。

| 遥控按键 | 功能 |
| --- | --- |
| `LEFT` | 选择并清空目标距离，随后用数字键输入毫米值，范围1~9999mm |
| `RIGHT` | 选择并清空目标速度，随后用数字键输入RPM，范围20~当前最大RPM |
| `UP/DOWN` | 选择底盘正向/反向 |
| `POWER` | 启动；运行中再次按下立即停止 |
| `VOL-/VOL+` | 离开页面并停止当前标定 |

该页面按调试要求临时忽略PD8/PB12的初始遮挡和运行途中的所有挡片，只根据编码器距离停车；退出、完成、手动停止、超时、急停或故障后自动恢复正常光电停车。测试必须选择无碰撞风险的直线路径并准备硬件急停，不能把场地挡片当作本页的安全限位。

程序停车后用卷尺测量底盘实际距离`D_actual`，与输入目标`D_target`比较。若保持车轮周长`263.9mm`不变，建议编码器每圈计数为：

```text
counts_per_rev_new = counts_per_rev_old * D_target / D_actual
```

例如输入1000mm、当前374计数/圈，实测行驶1050mm，则新值约为`374*1000/1050=356.2计数/圈`。建议正向和反向各测试至少三次，使用实际距离平均值计算；如果四轮“差”持续较大，应先检查轮胎打滑、编码器极性、机械阻力和闭环同步参数，而不是直接修改周长或每圈计数。

步进手动页用于距离标定：`RIGHT`切换X/Z轴，`UP/DOWN`选择方向，`POWER`启停，停止后按`0`清零当前轴带符号累计脉冲。正向脉冲累计为正，反向累计为负。

定量脉冲页用于指定步数测试：数字键逐位输入目标脉冲，`LEFT`删除末位，`RIGHT`切换X/Z轴，`UP/DOWN`选择方向，`POWER`启动或中途停止。运行期间禁止修改目标、轴和方向，页面显示目标与实际完成脉冲。

箱位标定页用于记录五个数字箱物理槽位的X轴坐标。槽位1~3依次为底部左、中、右，槽位4~5为两侧凸出箱位的左、右。进入本页前必须确认Z轴挡片已经离开共用PB11光电门，且标定过程中禁止Z轴运动。

1. 按`LEFT`让X轴向负方向点动，直到右端光电门触发并由软件记录为X轴限位。
2. 保持光电门遮挡时按`0`，将当前位置建立为`X=0`；若当前限位归属于Z轴，清零会被拒绝。
3. 按`RIGHT`沿X正方向点动，`UP/DOWN`在10、50、100、500、1000脉冲五档之间调整单次步长。

5. 页面中的`零:已/未`表示X参考点是否有效，`存:已/未`表示当前所选槽位是否已经保存。

### 槽位旋转姿态

世界地图的每个箱位带有`tool_yaw_degrees`规定逻辑角度。三个豆子箱在夹取前均使用初始`0°`姿态；数字区底部左、中、右三个横排箱在下降放豆前先旋转到`90°`；数字区两侧凸出箱保持初始`0°`，无需旋转。动作顺序必须是“Z轴处于安全高度 -> 旋转舵机到槽位角度 -> 等待稳定 -> Z轴下降 -> 夹爪释放 -> Z轴抬升”，禁止在夹爪已经伸入箱体后旋转。

地图保存的是规定逻辑角度，旋转舵机驱动会自动叠加已标定的`6°`安装偏移，因此上层不得把90度手工改成96度。离开一个箱位并抬升到安全高度后，应将旋转舵机恢复规定`0°`，再进行下一段底盘或X轴运动。

### 初始化调试页

“回零控制”页提供一键初始化调试。规定启动姿态为底盘停在场地起点，PD8和PB12均被起点两侧挡片遮挡，X轴夹爪位于横梁中点且Z轴触底。两路底盘光电门的高电平在该姿态下属于正常现象，本流程不会启动底盘，也不使用它们判断X/Z位置。

按`POWER`后以非阻塞状态机依次执行：确认或向下寻找Z触底PB11 -> 将触底点记为`Z=5784` -> 上升5784脉冲到最高点`Z=0` -> X向右寻找PB11并建立`X=0` -> 沿`+X`移动16962脉冲回到横梁中点 -> Z向下再次寻找PB11并恢复触底位置。每次改变运动方向时先关闭脉冲、写入DIR，再非阻塞等待300ms后启动，OLED在此期间显示“换向等待”。完成后OLED显示“完成”，X坐标为16962、Z坐标为5784，Z轴继续保持使能以防夹爪下滑。

- `POWER`：待机、完成或故障状态下开始；运行中再次按下会立即中止。
- `0`：立即中止并停止X/Z脉冲，Z轴仍按正常策略保持使能。
- `VOL-/VOL+`：离开页面时自动中止，防止调试动作在后台继续。
- 每个找限位或定量移动阶段均带独立超时；PB11没有在预期时间触发、有限脉冲提前中断、安全限位或急停都会进入“故障”。

X/Z共用PB11，因此流程严格串行，任何时刻只允许一个步进轴运动。最终回到X中点后才允许Z下降触底，避免X端部挡片与Z触底挡片同时遮住光束。该流程只适用于上述已知起始姿态；如果X实际停在端部却把PB11遮挡误认为Z触底，会破坏限位归属，必须先人工恢复到规定姿态。

### B-C-A连续抓豆Demo

“B-C-A抓豆”页用于从比赛起点规定姿态连续验证三个豆子箱。启动前必须满足：底盘位于起点两侧挡板、X轴在横梁中点、Z轴触底并遮挡PB11。遥控器按`POWER`启动，按`0`或离开页面立即停止底盘和X/Z轴。

启动后先让Z从触底位置升到`Z=0`，再让X寻找右端PB11、建立`X=0`并退出500脉冲。随后底盘以闭环`50 RPM`向豆子区运行：起点到B箱总路程使用实测`858+611+327=1796mm`，两侧光电门分别连续计数上障碍下侧、上障碍上侧/豆子识别和B夹取三组挡板。每组挡板的单侧触发只锁存事件，四轮继续行驶；两侧确认同组挡板后，前两组统一清零四轮速度环并从0同步续行，第3组B挡板则四轮同时停车并执行抓取。

B箱抓取并抬到`Z=0`后，夹爪在B箱正上方张开，把测试豆放回原箱；底盘继续以`50 RPM`运行`257mm`并在下一组A/C夹取挡板停车。A/C共用Y地标，因此先按C箱坐标`X=6700、Z=3290`抓取并原位释放，再保持底盘不动，按A箱坐标`X=26500、Z=4300`完成最后一次抓取。每次X横移都在`Z=0`进行，每次到站均要求PD8/PB12两侧挡板完成同组确认；单侧锁存后另一侧超过0.6秒仍未触发、路线超时、里程明显异常、急停或步进限位异常都会进入故障并停机。

### 数字区放豆演示页

“放豆控制”页用于实机演示数字区底部左、中、右三个横排箱位的连续放豆动作。该页采用人工确认起始姿态：启动前由操作者确保X轴位于右端`X=0`、Z轴位于最高点`Z=0`；按`POWER`后程序直接将当前脉冲坐标写为X=0、Z=0，不再要求先进入X/Z标定页面。若PB11因X右端挡片而处于遮挡，程序会将当前遮挡认领为X右端限位，并只允许X沿正方向离开。

此放宽仅用于人工看护下的Demo。若实际姿态不是X右端和Z最高点，软件仍会错误地把当前位置当作零点，可能导致箱位错位或碰撞；正式自动比赛流程仍必须使用传感器回零确认，不能沿用人工假定。

- `POWER`：开始、暂停或继续演示。
- `0`：立即中止演示，停止X/Z轴，并让旋转舵机恢复规定0度、夹爪恢复闭合10度。
- `VOL-/VOL+`或板载翻页键：离开演示页时自动中止演示。

每个箱位的非阻塞动作顺序为：Z升到0 -> X移动到槽位 -> 旋转舵机到90度并等待600ms -> Z下降到3300 -> 夹爪张开到45度并保持900ms -> Z升到0 -> 旋转舵机回0度、夹爪回10度 -> 进入下一箱。OLED实时显示箱位、阶段以及X/Z坐标。演示仅验证动作和防碰撞顺序，不代表夹爪中实际装有三份豆子。

夹爪被豆子阻挡时，普通位置舵机无法反馈实际闭合角度，持续命令10度只能提供保持力，不能保证豆子不会滑落。机械上应优先采用软硅胶防滑面、弹簧顺应连接和能托底的半封闭爪形，避免仅靠两片硬爪摩擦夹持散料。软件抓取流程后续采用“闭合保持 -> 小幅试抬 -> 再次保持闭合 -> 正式抬升”，并预留舵机电流或指端压力检测接口；没有力反馈时必须限制堵转保持时间，防止舵机过热。

## 8. FreeRTOS 任务

当前任务来自 `Crane_rtos.ioc`：

| 任务 | 入口 | 优先级 | 栈配置 |
| --- | --- | ---: | ---: |
| APP_CTRL | `StartAppCtrlTask` | 24 | 192 words |
| DC_MOTOR | `StartDcMotorTask` | 32 | 256 words |
| K230_RX | `StartK230RxTask` | 24 | 256 words |
| INPUT_EVT | `StartInputEvtTask` | 32 | 192 words |
| OLED | `StartOledTask` | 8 | 256 words |
| IR_REMOTE | `StartInfraredTask` | 24 | 192 words |

FreeRTOS 动态堆当前为 12288 字节。底盘任务以 10ms 周期运行；应用控制、OLED 和红外任务使用绝对周期延时，避免长期漂移。步进换向状态机已合并进应用控制任务，减少一个常驻任务及其栈开销。`K230_RX` 任务和 USART2/DMA 配置继续保留，但运行时开关关闭时任务仅低频休眠，不进行收发。限位和急停的硬件中断只做快速转发，消抖和业务处理在任务/安全模块中完成。

## 9. K230 运行文件

K230 Python 程序不参与 STM32 CMake 构建。K230 端需要单独准备：

```text
/sdcard/number/main.py
/sdcard/number/deploy_config.json
/sdcard/number/<kmodel文件>
```

模型路径、类别、输入尺寸和阈值由 `deploy_config.json` 决定。K230 的串口编号属于 K230 自己的硬件定义，不等同于 STM32 的 USART 编号；当前物理连接对应 STM32 USART2。

## 10. 新开发者建议流程

1. 克隆仓库并确认 Git、CMake、Ninja、ARM GCC 都能在命令行执行。
2. 使用 `cmake --preset Debug` 和 `cmake --build --preset Debug` 编译。
3. 打开 `Crane_rtos.ioc`，确认生成配置和引脚标签，再生成代码并重新编译。
4. 不接电机时先烧录，确认 OLED、按键、串口和限位输入。
5. 单独验证 Z 轴、舵机、M1，再逐步接入 M2 至 M4。
6. 校准编码器每圈计数、极性、底盘直行和光电限位位置。
7. 最后接入 K230 视觉结果、路线参数和自动比赛状态机。
# 摄像头俯仰舵机

- PWM 信号：`PB8 / TIM4_CH3`
- 定时器：`PSC=71`、`ARR=19999`，计数分辨率 `1us`，周期 `20ms`
- 平视位置：`CCR=1700`
- 俯视位置：`CCR=2500`
- 上电默认：平视
- 蜂鸣器因 PB8 改作 PWM，信号线迁移到 `PE6`
- 舵机必须使用独立的合适电源供电，并与 STM32、红外接收模块共地
- 控制接口位于 `camera_tilt.h`：`CameraTilt_SetLevel()`、`CameraTilt_SetDown()`、
  `CameraTilt_SetPulseUs()`

## 光电传感器预留

- 传感器1：`PB11 / EXTI11`
- 传感器2：`PB12 / EXTI12`
- 传感器3：`PD8 / EXTI8`

底盘两侧光电门按世界坐标方向固定定义：靠近场地右上角坐标原点的一侧接`PD8`（业务名`PHOTO_SENSOR_CHASSIS_ORIGIN_SIDE`），另一侧即远离原点的一侧接`PB12`（业务名`PHOTO_SENSOR_CHASSIS_FAR_SIDE`）。路线与到站代码必须使用这两个方向名称，不使用观察者视角下容易变化的“左/右”名称。`PB11`继续作为X/Z轴共用光电门（业务名`PHOTO_SENSOR_SHARED_XZ`）。

底盘手动调试已启用两侧独立光电到站停车：原点侧`PD8`只控制M1/M2，远端侧`PB12`只控制M3/M4。每次按`POWER`时不检查当前光电电平，四台电机始终允许启动；当前已遮挡的一侧先等待传感器恢复0，当前无遮挡的一侧立即布防。之后PD8下一次变为1时只将M1/M2输出清零，PB12下一次变为1时只将M3/M4输出清零，另一侧继续运行以完成机械对齐；两侧都触发后底盘整体停止。

底盘OLED页中`M12/M34`的1表示该侧仍在运行，0表示该侧已停车；`原/远`分别显示PD8和PB12原始电平；`防`后两位依次表示M1/M2侧和M3/M4侧是否已经布防。该功能用于测量两侧独立停车惯性，实际停车距离仍受车速、负载、地面和机械制动能力影响。
- 三路均为上拉输入、上升沿和下降沿中断
- `PhotoSensor_GetState()`返回GPIO原始电平；各传感器的遮挡极性按实测配置
- `PB13/PB14` 没有用于传感器中断，因为 EXTI13/14 已分配给
  `PD13/PD14` 的底盘编码器
- 三路均记录实时电平和变化标志；传感器2、3暂不执行运动控制
- 传感器1（`PB11`）实测为无遮挡低电平、遮挡高电平，作为X/Z两轴共用方向限位
- X轴和Z轴复用的是同一个PB11光电门，不是两套独立限位；机械设计和路线均不允许两个轴的挡片同时遮挡光束
- 驱动层强制X/Z运动互斥：任一轴正在输出脉冲时，另一轴的启动请求会被拒绝，保证光电门触发归属唯一
- 任一轴运动时触发PB11，最迟在10ms控制周期内记录触发轴和方向并停止该轴
- 遮挡期间仅允许触发轴沿相反方向脱离，原方向和另一轴均禁止启动
- 光束恢复后自动解除方向限位；上电时已经遮挡且没有触发记录时，两轴均禁止启动
- Z轴正常停止或触发光电门时仅关闭PUL脉冲，TB6600的ENA保持低电平以提供静态保持转矩
- X轴正常停止仍释放驱动；Z轴因承受夹爪重力，在`StepperAxis_Init()`完成后立即拉低TB6600 ENA进入静态保持，不输出PWM脉冲，上电后即具有保持力。Z轴每次正常运动停止后也继续保持；急停和安全故障调用`StepperAxis_StopAll()`时两轴仍会彻底释放
- Z轴保持会持续产生线圈电流和热量，应根据负载调整TB6600电流档位并检查电机温升
- `StepperAxis_MovePulses(axis, pulse_count, reverse)`可非阻塞输出指定数量的步进脉冲
- TIM1捕获比较中断在每个完整脉冲下降沿计数，达到目标后自动停止；X轴释放、Z轴进入保持
- 可通过`StepperAxis_GetCommandedPulses()`、`GetCompletedPulses()`和`GetRemainingPulses()`记录标定数据
- 指定脉冲运动中若触发光电门或安全停机，本次运动会被取消，已完成计数保留供诊断

### 步进轴实机标定（2026-07-26）

| 轴 | 实测基准 | 脉冲数 | 换算结果 | 建议安全工作行程 |
| --- | --- | ---: | ---: | ---: |
| X轴 | 两端光电门之间约169.3cm | 33924 | 约200.38脉冲/cm，0.04991mm/脉冲 | 33424脉冲，预留500脉冲约2.50cm |
| Z轴 | 夹爪触底遮挡光电门至向上最大28.1cm | 5784 | 约205.84脉冲/cm，0.04858mm/脉冲 | 5584脉冲，上端预留200脉冲约0.97cm |

- `app_config.h`集中保存上述标定值，路线规划优先使用安全工作行程，不要直接使用机械全行程。
- 单次`StepperAxis_MovePulses()`指令不得超过对应轴的实测完整行程，超出时返回`HAL_ERROR`且不会启动。
- 当前脉冲累计值是软件输出计数，上电后不是可信绝对坐标；可先在“回零控制”页完成X/Z初始化，只有PB11确认触底和X右端零点后，绝对坐标才可信。
- X轴两端光电门和Z轴触底光电门继续承担硬限位。调试新路线时应先低速、短距离运行，再逐步扩大行程。
- Z轴停止后保持使能以防夹爪下滑；长期保持时检查步进电机和TB6600温升，急停时仍会释放两轴驱动。

## K230视觉通信协议

- STM32 USART2：`PA2 TX`、`PA3 RX`，`115200 8N1`，RX/TX均使用DMA
- K230 UART1：`IO40 TX`、`IO41 RX`，与STM32交叉连接并共地
- STM32默认每200ms发送一次单次识别请求，不在中断中解析协议
- DMA回调只把数据写入512字节环形缓冲；`K230_RX`任务负责组帧、CRC和结果发布
- 帧格式：`AA 55 | 版本 | 命令 | 序号LE16 | 负载长度LE16 | 负载 | CRC16/MODBUS`
- 请求命令：`0x10`单次、`0x11`开始流、`0x12`停止流、`0x20`切换任务
- 响应命令：`0x90`识别结果、`0xA0`任务切换确认；切换任务负载为1字节任务ID
- 结果负载：任务类型、目标数量，以及每个目标的语义、置信度、中心X和中心Y
- 最多保存16个目标；数字语义为`1~5`，豆子语义为`0x11/0x12/0x13`
- `K230Link_GetLatestResult()`提供一致的完整快照，供后续路线规划读取
- 超过1.2秒没有合法结果帧时，系统将视觉状态标记为离线
- OLED视觉页按K230返回的640像素横坐标实时显示目标位置：数字模式使用5个固定位置框，豆子模式使用3个固定位置框；同一区域出现多个目标时显示置信度最高的目标
- 视觉页待机时按遥控器`1`选择数字识别、按`2`选择豆子识别；`POWER`启动/停止完整视觉路线Demo，`0`立即停止Demo
- 模型切换期间暂停识别请求，收到K230的ACK后清除旧结果并恢复5Hz单次请求

### 视觉路线Demo

`vision_route_demo.c/.h`用于在正式搬运状态机尚未全部联调前，独立验证“初始化定位 -> 数字识别 -> 豆子识别”整条链路。进入OLED视觉页并按`POWER`后，非阻塞状态机会连续执行完整识别路线；再次按`POWER`或按`0`均可中止。

1. 按比赛起始姿态把Z触底位置认作`5784`脉冲，抬升约`1544`脉冲到离地约75mm的识别安全高度（绝对`Z≈4240`）。
2. X轴向右端寻找共用光电门并建立`X=0`，换向等待300ms后移动`8500`脉冲到物理2号箱对应位置。
3. 底盘从起点以`50RPM`经过下障碍上侧挡板完成两侧对齐，再自动前往数字识别挡板。
4. 到达数字识别点后，摄像头保持平视、旋转舵机为规定`0°`；先在`X=8500`观察右侧横箱，再沿`+X`连续扫描，经过中箱`X=16300`并到达左侧横箱`X=24400`。
5. 横排扫描完成后，旋转舵机转到规定`54°`观察侧箱并停留约1秒；随后转到`180°`，底盘从数字识别点沿每组已标定挡板以`50RPM`连续分段运行至豆子识别点。
6. 到达豆子识别点后摄像头俯视，先以规定`180°`观察A箱，再转到`194°`观察B箱，每个姿态停留约1秒后完成。C箱可在正式识别逻辑中用排除法补齐。
7. 数字区始终显示5个固定框，豆子区始终显示3个固定框。K230有结果时实时填入，但Demo不等待模型切换ACK、识别帧或完整结果，未连接摄像头也能完整演示机构路线。

当前Demo只验证机构动作、挡板定位和整条运动路线，视觉通信完全不参与状态跳转。路线超时、急停/限位故障或X/Z回零异常仍会立即进入故障并停机。

每个Y路线段都从一对挡板出发并在下一对挡板确认。PD8、PB12任一侧先触发时只锁存事件，不停止对应轮组；另一侧超过0.6秒仍未触发时判定为漏检或严重歪斜，立即停止整车并令路线失败。每侧触发时还会读取本侧两个编码器的平均行程，当前宽松接受范围为理论值的`45%~165%`：低于下限的遮挡视为当前挡板残留、停车滑移回弹或边沿抖动，直接忽略且不推进路线；高于上限才作为漏站或编码器异常报错。范围以内一律以光电门位置为准。OLED行进页中的“到”是已经锁存本组事件的侧掩码，“行”在双侧确认前仍保持两侧运行；位0对应M1/M2侧，位1对应M3/M4侧。

该Demo只验证视觉巡检路线和显示，不会自动生成并执行抓放任务。数字/豆子框目前按单帧内640像素横坐标分区，再用跨帧确认抑制跳变；后续标定A/B/C具体扫描姿态后，再把相机位姿和X轴绝对坐标融合成正式物理箱位映射。
