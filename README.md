# Crane_rtos

基于 STM32F103ZET6、FreeRTOS、CubeMX 和 CMake 的起重式散料货物搬运机器人控制工程。

项目面向物流技术创意赛运输豆子任务，目标是让机器人完成自主识别、取料、绕障运输、准确放料和归位。当前工程已经完成硬件控制框架和分模块调试基础，完整视觉搬运流程仍需结合实机继续开发。

## 1. 项目状态

当前已经具备：

- 双 TB6600 步进轴的启停、方向和使能控制；X/Z 两轴已接线并完成红外手动控制验证，当前速度合适。
- 四路 L298N 直流电机双 PWM 驱动结构；四轮方向、编码器测速和闭环同步控速已完成实机验证。
- 两路舵机 PWM；PA0 旋转舵机和 PA1 夹爪舵机均已完成关键角度实机标定。
- K230 USART2 DMA 收发框架已保留，当前运行时收发关闭。
- OLED 五页全中文状态界面。
- 急停、四路对射光电限位和 EXTI 事件框架。
- FreeRTOS 任务框架、独立红外任务、路线表和比赛状态机骨架。

自动状态机目前默认停在 `VISION_SCAN`，不会在硬件未接齐时自动驱动机器人跑路线。

### 2026-07-17 舵机与红外调试进度

- PA0 / TIM2_CH1 为 270 度旋转舵机；规定 0 度对应舵机实际 6 度，后续规定角度统一叠加 6 度安装偏移。
- PA1 / TIM2_CH2 为 180 度夹爪舵机；实机确认 `10°` 完全闭合、`45°` 可完全放下豆子、`100°` 是能伸入放置盒的最大张角。
- TIM4_CH4 / PB9 已接入 NEC 红外解码，并新增独立 `IR_REMOTE` FreeRTOS 任务处理所有有效按键。
- 该阶段的夹爪红外演示绑定已经解除，当前红外按键改用于 X/Z 步进轴手动调试，映射见“红外遥控”章节。

### 2026-07-19 双步进轴红外调试进度

- X/Z 两轴均使用 TB6600 的 4 细分，即 `800` 脉冲/圈；TIM1 当前为 `PSC=71`、`ARR=399`，脉冲频率约 `2.5kHz`。
- 运行时 CCR 为 `250`；TB6600 按脉冲边沿计步，占空比不决定转速。按 800 脉冲/圈计算，理论电机转速约 `187.5RPM`。实机确认当前两轴速度合适，暂不提高频率或修改细分。
- 遥控器数字 `1/2` 分别选择 X/Z 轴；`LEFT/RIGHT` 设置 X 轴反/正转，`UP/DOWN` 设置 Z 轴正/反转，`POWER` 启停当前轴。
- 手动调试采用单轴互锁：切换控制轴时先停止原轴，防止两轴意外同时运行。
- 运行中反向时先停止并缓存目标方向，等待 `300ms` 后再恢复；等待期间按 `POWER` 会取消换向并保持停止。
- 急停或任一限位故障存在时，两轴停止且红外命令不能重新启动电机。
- OLED 步进页面已完成中文显示：遥控步进、选择轴、运行状态、方向状态和换向等待。
- 每个通过 NEC 校验的遥控按键都会触发 PB8 蜂鸣器短响约 60ms；采用非阻塞定时关闭，不影响红外解码和换向状态机。安全故障下蜂鸣仍表示按键码已收到，但不会执行电机动作。

### 2026-07-23 全机构遥控与 OLED 调试界面

- 遥控器采用“当前页面决定控制对象”：`VOL-/VOL+` 或 K0/K1 翻页；步进页内 `2/3` 选择 X/Z，舵机页内 `4/5` 选择旋转/夹爪，底盘页内 `6/7/8` 调整底盘。
- 四个直流电机不再支持单轮遥控，底盘始终四轮整体启停和整体换向。
- `VOL- / VOL+` 切换 OLED 上一页/下一页；开机进入总览页。
- `0` 为软件总停止，关闭四轮底盘和 X/Z 步进轴；舵机保持当前位置。
- 切换控制对象时先停止此前选中的底盘或步进轴，避免运动机构在后台继续运行。

```powershell

ninja --version
```

## 4. 克隆后首次构建

在仓库根目录执行：

```powershell
git clone <仓库地址>
cd Crane_rtos
cmake --preset Debug
cmake --build --preset Debug
```

或者使用已经生成的构建目录：

```powershell
cmake --build build\Debug
```

成功后主要产物为：

```text
build/Debug/Crane_rtos.elf
```

Release 构建：

```powershell
cmake --preset Release
cmake --build --preset Release
```

如果首次构建报 `arm-none-eabi-gcc is not recognized`，这是本机工具链 PATH 问题，不是项目源码问题。若报 `ninja is not recognized`，安装 Ninja 并加入 PATH，或在 CMake 中改用本机可用的生成器。

## 5. CubeMX 配置与重新生成

CubeMX 工程文件为：

```text
Crane_rtos.ioc
```

打开后修改引脚、定时器、DMA、FreeRTOS 或 NVIC 配置，再点击 **Generate Code**。生成完成后必须重新构建：

```powershell
cmake --build --preset Debug
```

生成后至少检查：

- `Core/Inc/main.h` 的标签与预期一致。
- `Core/Src/main.c` 中 `MX_TIM8_Init()` 存在。
- TIM3/TIM8 四通道 PWM 存在。
- USART2 DMA RX/TX 和空闲线接收存在。
- `PC5 / LIMIT_Z_MIN` 为 `GPIO_MODE_IT_RISING + GPIO_PULLDOWN`。
- `PE0/PE1/PE2` 同样为高有效限位输入。
- `EXTI9_5_IRQHandler` 同时转发 `LIMIT_Z_MIN_Pin` 和 `ESTOP_IN_Pin`。

CubeMX 可能重写生成区域，因此手写业务应放在 `USER CODE` 区域或独立 `.c/.h` 文件。修改 `.ioc` 后不要只修改生成的 `main.c`，否则下次生成可能丢失配置。

## 6. 烧录与调试

项目当前没有把 STM32CubeProgrammer 或 ST-LINK 的绝对路径写入 CMake，也没有固定烧录脚本。不同电脑只需要在本机安装工具并替换命令路径。

推荐使用 SWD：

| ST-LINK | STM32 |
| --- | --- |
| SWDIO | PA13 |
| SWCLK | PA14 |
| GND | GND |
| 3.3V | 目标板 3.3V 检测/供电，按调试器要求连接 |
| NRST | NRST，可选但建议连接 |

生成 Intel HEX 或 BIN：

```powershell
arm-none-eabi-objcopy -O ihex build\Debug\Crane_rtos.elf build\Debug\Crane_rtos.hex
arm-none-eabi-objcopy -O binary build\Debug\Crane_rtos.elf build\Debug\Crane_rtos.bin
```

使用 STM32CubeProgrammer CLI 烧录时，命令格式通常为：

```powershell
STM32_Programmer_CLI.exe -c port=SWD -w build\Debug\Crane_rtos.elf -v -rst
```

如果命令找不到，请使用本机 STM32CubeProgrammer 安装目录中的 `STM32_Programmer_CLI.exe` 的绝对路径。也可以使用 STM32CubeProgrammer 图形界面选择 `Crane_rtos.elf`、连接方式 `ST-LINK/SWD` 后下载。

烧录前确认：目标板供电正常、ST-LINK 电压与目标板一致、所有电机驱动器处于安全停止状态。

## 7. 硬件基线

### 直流电机与编码器

四路直流电机由集成两颗 L298N 的四路驱动板控制。电机使用 12V，编码器统一使用 STM32 的 3.3V。接线或改线前必须同时关闭 12V 电机电源和控制板电源。

#### 电源与共地

```text
12V电源正极  -> L298N VCC / 电机电源+
12V电源负极  -> L298N GND
STM32 GND     -> L298N GND
编码器黑线    -> STM32 GND
```

12V 电源负极、L298N GND、STM32 GND 和四个编码器黑线必须共地。模块自带的 5V 输出暂不连接 STM32，避免与控制板自身电源互相倒灌。编码器蓝线严禁接入 12V。

#### 电机输出与控制输入

| 电机 | STM32 PWM 1 | L298N输入 | STM32 PWM 2 | L298N输入 | 电机红/白线 |
| --- | --- | --- | --- | --- | --- |
| M1 | PA6 / TIM3_CH1 | IN1 | PA7 / TIM3_CH2 | IN2 | OUT1 / OUT2 |
| M2 | PB0 / TIM3_CH3 | IN3 | PB1 / TIM3_CH4 | IN4 | OUT3 / OUT4 |
| M3 | PC6 / TIM8_CH1 | IN5 | PC7 / TIM8_CH2 | IN6 | OUT5 / OUT6 |
| M4 | PC8 / TIM8_CH3 | IN7 | PC9 / TIM8_CH4 | IN8 | OUT7 / OUT8 |

L298N 的 EN1 至 EN4 只保持使能，不承担 PWM。如果驱动板带 EN 跳帽，调试时保留跳帽；如果是独立 EN 输入，则按照模块说明置于有效电平。当前软件采用双 PWM 控制：

```text
正转：IN1=PWM，IN2=0
反转：IN1=0，IN2=PWM
停止：IN1=0，IN2=0
```

TIM3 控制 M1/M2，TIM8 控制 M3/M4，两者当前均为约 10kHz PWM。STM32 的 3.3V 高电平满足该模块标注的 2.3V 以上有效输入要求。

#### 编码器接线

每个电机的六根线定义：

```text
红线 -> 电机端，接对应 OUT 奇数端
白线 -> 电机端，接对应 OUT 偶数端
蓝线 -> STM32 3.3V
黑线 -> STM32 GND
黄线 -> 编码器 A 相
绿线 -> 编码器 B 相
```

| 电机 | 黄线 A | 绿线 B | 蓝线 | 黑线 |
| --- | --- | --- | --- | --- |
| M1 | PD10 | PD4 | 3.3V | GND |
| M2 | PD13 | PD5 | 3.3V | GND |
| M3 | PD14 | PD6 | 3.3V | GND |
| M4 | PD15 | PD7 | 3.3V | GND |

编码器 A 相使用上升沿 EXTI，B 相作为方向判定输入，两者均启用内部上拉。电机资料标注电机轴每圈 11 个反馈信号；当前配置中的输出轴每圈计数 `374` 是暂定值，闭环控制前必须结合减速比和实际计数方式重新标定。

#### 电流、散热与首次上电

驱动板标注的 2A 通常指单路电机桥的短时峰值，不是四路模块总共只有 2A，也不代表四路可以长期各输出 2A。建议将单路连续电流控制在约 0.8～1.2A 范围内，具体上限取决于散热片、风冷和 PCB 走线。四路总电流还受 12V 电源额定电流限制。

首次上电按以下顺序进行：

1. 将车架架空，确保四个轮子均不接触地面。
2. 断电状态下检查 12V 与 3.3V 之间不存在短路。
3. 只连接 M1，电源设为 12V、约 1A 限流，验证正反转和编码器计数。
4. 依次接入 M2、M3、M4，每增加一路都检查空载电流和 L298N 温升。
5. 四路空载正常后再逐步提高总限流，12V/5A 电源最大只能提供约 5A 总电流。
6. 确认急停、停止命令和软件 PWM 均有效后，再让轮子落地低速测试。

如果某个轮子的正转方向与整车定义相反，优先调整 `motor_polarity[]`，也可以断电后交换该电机红白线。编码器方向错误时再交换黄绿线或调整编码器极性，避免一次同时改变电机线和编码器线而难以定位问题。

当前实机规定正方向已经标定：M1、M2 的安装方向与 M3、M4 相反，因此固定使用 `motor_polarity = {-1, -1, 1, 1}`。上层底盘和路线代码只使用统一的正负速度定义，不应再次针对 M1/M2 单独交换方向。

2026-07-23 串口闭环遥测确认：开环规定正向下 M1/M2 原始编码器计数为负，因此反馈配置固定为 `encoder_polarity = {-1, -1, 1, 1}`。同时实机的 M3/M4 驱动线序与最初逻辑标号交叉，软件已交换 TIM8_CH1/2 与 TIM8_CH3/4 的逻辑映射，使 P3 对应编码器3、P4对应编码器4。该修正不改变四轮已经验证正确的开环物理正方向。

### 步进轴

| 轴 | PUL | DIR | ENA |
| --- | --- | --- | --- |
| X | PE9 / TIM1_CH1 | PD2 | PD11 |
| Z | PE11 / TIM1_CH2 | PD3 | PD12 |

TB6600 ENA 低电平有效。X/Z 两轴当前均使用 4 细分、800 脉冲/圈；TIM1 `PSC=71`、`ARR=399`，约 2.5kHz，运行 CCR 为 250。理论转速约 187.5RPM，当前实机速度已确认合适。

### 舵机、OLED、K230

- 旋转舵机：PA0 / TIM2_CH1，物理范围 0～270 度，对应 500～2500μs；规定角度自动增加 6 度安装偏移，上电和遥控复位显示为规定 0 度，实际输出 6 度。
- 夹爪舵机：PA1 / TIM2_CH2，范围 0～180 度，对应 1000～2000μs；闭合/放豆/最大张角分别为 10/45/100 度，上电和遥控复位到闭合的 10 度。
- 两路舵机遥控 UP/DOWN 每次增减 10 度。旋转规定角限制为 0～264 度，夹爪工作角限制为 10～100 度，超过边界的命令自动夹紧。两路均为 50Hz，并使用独立 5V/6V 电源。
- OLED：PB6/PB7 / I2C1，SSD1306，常用地址 0x3C。
- K230 预留：PA2 为 USART2_TX，PA3 为 USART2_RX，115200 8N1，DMA RX/TX。当前 `K230_LINK_RUNTIME_ENABLED=0U`，不启动 DMA 接收也不发送信息；接入 K230 后改为 `1U`。

### 按键、急停、对射光电

- K0：PE4，低有效下降沿；K1：PE3，低有效下降沿；急停：PE7，低有效下降沿。
- K0/K1 当前只切换 OLED 上一页/下一页，不直接驱动执行机构；当前运动调试统一通过红外遥控完成。
- X 最小/最大：PE0/PE1；Z 上/下：PE2/PC5。
- 光电模块无遮挡 `DO=低`、遮挡 `DO=高`，四路限位使用内部下拉和上升沿 EXTI。
- 光电模块只有在 DO 高电平不超过 3.3V 时才能直接连接 STM32；高于 3.3V 必须做电平转换。

### 红外遥控

- 接收端 DO：PB9 / TIM4_CH4，标签 `IR_REMOTE_RX`；应连接 3.3V 逻辑电平的解调型红外接收模块，且必须与 STM32 共地。
- TIM4：CH4 在 CubeMX 中配置为上升沿输入捕获、`PSC=71`、`ARR=65535`，计数分辨率为 1 us；软件在每次捕获后交替切换边沿以完成 NEC 解码。必须启用 `TIM4_IRQn`，不要将其再用作 HAL 时基。

| 按键 | NEC 命令码 | 当前功能 |
| --- | ---: | --- |
| 1 | `0x16` | 当前保留，不跨页面切换机构 |
| 2 | `0x19` | 仅在步进页选择 X 轴 |
| 3 | `0x0D` | 仅在步进页选择 Z 轴 |
| 4 | `0x0C` | 仅在舵机页选择旋转舵机（PA0） |
| 5 | `0x18` | 仅在舵机页选择夹爪舵机（PA1） |
| 6 | `0x5E` | 仅在底盘页且停止时切换开环/四轮闭环 |
| 7 / 8 | `0x08` / `0x1C` | 仅在底盘页将闭环目标转速减/增 10 RPM |
| UP | `0x46` | 底盘/步进设正向，舵机增加 10 度 |
| DOWN | `0x15` | 底盘/步进设反向，舵机减少 10 度 |
| POWER | `0x45` | 底盘/步进启停；旋转舵机回规定0度，夹爪回闭合10度 |
| 0 | `0x42` | 软件总停止：底盘和双步进轴停止 |
| VOL- | `0x07` | OLED 上一页 |
| VOL+ | `0x09` | OLED 下一页 |

UP、DOWN和POWER只作用于当前OLED页面；总览页和系统页不响应机构动作。离开底盘或步进页面时先停止原机构，防止后台继续运动。底盘遥控占空比固定为 `75/99`。底盘和步进电机只有在停止状态下才能改变方向；步进运行中收到反向命令时仍采用300ms停机死区。急停和限位故障优先级最高，故障状态仅允许OLED翻页，不执行运动命令。

底盘默认处于 `CLOSED` 闭环模式，默认目标速度为 `110 RPM`，但上电保持停止，收到明确启动命令后才运动。按 `6` 可在底盘停止时切换开环/闭环，按 `7/8` 调整目标转速。闭环模式使用四轮独立 PI、速度前馈和平均速度同步补偿；开环模式仅用于检查驱动、编码器计数和物理方向。

四轮测速仍以 10ms 周期执行控制，但将编码器增量累计 50ms 后再计算 RPM，降低低脉冲数造成的显示跳变。闭环停止命令会立即将四路 PWM 清零；同向速度控制禁止跨零输出反向制动力，避免某轮超调时突然反转。现阶段不加入 D 项，因为编码器量化噪声会被微分项显著放大。

2026-07-23 实机在线调参结果：`KP=0.8`、`KI=2.5`、`FF=0.65`、`SYNC=0.2` 保持不变，测速滤波系数由 `0.35` 优化为 `0.25`。在架空空载测试中，40/60/80/100/120 RPM 均可稳定跟踪；40 RPM 时四轮平均瞬时离散度约 `0.88 RPM`，120 RPM 时约 `2.03 RPM`。这些参数是空载基线，底盘落地承载后仍需重新验证直线偏移和抗扰性能。

以下 USART2 遥测和在线调参协议代码仍保留，但当前运行时开关关闭，不会接收命令或输出 CSV。后续接入 K230 或继续串口调参时，先将 `K230_LINK_RUNTIME_ENABLED` 改为 `1U`。

启用后，USART2 可按 115200 8N1 输出 CSV：

```text
CSV:M,tick,closed,run,dir,target,r1,r2,r3,r4,p1,p2,p3,p4,c1,c2,c3,c4
M,12340,1,1,0,40,39,41,38,40,52,49,55,51,1024,1010,998,1018
```

`r1~r4` 为滤波后的整数 RPM，`p1~p4` 为控制器实际输出命令，`c1~c4` 为累计编码器计数。遥测由低优先级 UART 任务以约 20 Hz 格式化，并使用非阻塞 DMA 投递；串口忙时丢弃本帧，不占用 10ms 高优先级电机控制任务。

### 串口在线调参

USART2 使用 `115200 8N1`。在线参数只保存在 RAM 中，复位后恢复 `app_config.c` 默认值。所有命令以回车或换行结束：

| 命令 | 作用 |
| --- | --- |
| `MGET` | 查询当前四轮参数、目标转速、模式、启停和方向 |
| `MSET KP 1 0.8` | 修改 1 号电机比例增益；电机号可用 `1~4` 或 `ALL` |
| `MSET KI ALL 1.2` | 修改四轮积分增益 |
| `MSET FF ALL 1.5` | 修改四轮速度前馈 |
| `MSET SYNC ALL 0.2` | 修改四轮平均速度同步增益 |
| `MSET FILTER ALL 0.25` | 修改测速低通滤波系数，范围 `0.01~1.0` |
| `MTARGET 40` | 设置闭环目标转速，范围 `20~130 RPM` |
| `MMODE OPEN` / `MMODE CLOSED` | 切换开环/闭环，要求底盘已经停止 |
| `MDIR FWD` / `MDIR REV` | 切换规定正向/反向，要求底盘已经停止 |
| `MRUN 1` / `MRUN 0` | 四轮启动/停止 |

电脑端工具为 `tools/motor_tuner.py`，依赖 `pyserial`。默认使用 `COM14`：

```powershell
python -m pip install pyserial
python tools/motor_tuner.py --port COM14 send "MGET"
python tools/motor_tuner.py --port COM14 monitor --duration 10 --output telemetry.csv
python tools/motor_tuner.py --port COM14 step --target 40 --duration 12 --settle 3 --output motor_test.csv
```

`monitor` 只读取数据，不会启动电机。`step` 是明确的运动测试：先停止、配置模式/方向/目标，再启动；正常结束、Ctrl+C 或异常退出时都会请求 `MRUN 0`。测试前仍应架空四轮并准备硬件急停，串口断线时不能把软件停机当作唯一保护。

OLED操作页面包括：总览、底盘、步进手动、定量脉冲、舵机、视觉和系统。页面只显示状态并按当前页隔离遥控操作，不会跨页面误控机构。

步进手动页用于距离标定：`RIGHT`切换X/Z轴，`UP/DOWN`选择方向，`POWER`启停，停止后按`0`清零当前轴带符号累计脉冲。正向脉冲累计为正，反向累计为负。

定量脉冲页用于指定步数测试：数字键逐位输入目标脉冲，`LEFT`删除末位，`RIGHT`切换X/Z轴，`UP/DOWN`选择方向，`POWER`启动或中途停止。运行期间禁止修改目标、轴和方向，页面显示目标与实际完成脉冲。

## 8. FreeRTOS 任务

当前任务来自 `Crane_rtos.ioc`：

| 任务 | 入口 | 优先级 | 栈配置 |
| --- | --- | ---: | ---: |
| APP_CTRL | `StartAppCtrlTask` | 24 | 192 words |
| DC_MOTOR | `StartDcMotorTask` | 32 | 256 words |
| K230_RX | `StartK230RxTask` | 24 | 256 words |
| INPUT_EVT | `StartInputEvtTask` | 32 | 192 words |
| OLED | `StartOledTask` | 8 | 256 words |
| IR_REMOTE | `StartInfraredTask` | 24 | 192 words |

FreeRTOS 动态堆当前为 12288 字节。底盘任务以 10ms 周期运行；应用控制、OLED 和红外任务使用绝对周期延时，避免长期漂移。步进换向状态机已合并进应用控制任务，减少一个常驻任务及其栈开销。`K230_RX` 任务和 USART2/DMA 配置继续保留，但运行时开关关闭时任务仅低频休眠，不进行收发。限位和急停的硬件中断只做快速转发，消抖和业务处理在任务/安全模块中完成。

## 9. K230 运行文件

K230 Python 程序不参与 STM32 CMake 构建。K230 端需要单独准备：

```text
/sdcard/number/main.py
/sdcard/number/deploy_config.json
/sdcard/number/<kmodel文件>
```

模型路径、类别、输入尺寸和阈值由 `deploy_config.json` 决定。K230 的串口编号属于 K230 自己的硬件定义，不等同于 STM32 的 USART 编号；当前物理连接对应 STM32 USART2。

## 10. 新开发者建议流程

1. 克隆仓库并确认 Git、CMake、Ninja、ARM GCC 都能在命令行执行。
2. 使用 `cmake --preset Debug` 和 `cmake --build --preset Debug` 编译。
3. 打开 `Crane_rtos.ioc`，确认生成配置和引脚标签，再生成代码并重新编译。
4. 不接电机时先烧录，确认 OLED、按键、串口和限位输入。
5. 单独验证 Z 轴、舵机、M1，再逐步接入 M2 至 M4。
6. 校准编码器每圈计数、极性、底盘直行和光电限位位置。
7. 最后接入 K230 视觉结果、路线参数和自动比赛状态机。
# 摄像头俯仰舵机

- PWM 信号：`PB8 / TIM4_CH3`
- 定时器：`PSC=71`、`ARR=19999`，计数分辨率 `1us`，周期 `20ms`
- 平视位置：`CCR=1700`
- 俯视位置：`CCR=2500`
- 上电默认：平视
- 蜂鸣器因 PB8 改作 PWM，信号线迁移到 `PE6`
- 舵机必须使用独立的合适电源供电，并与 STM32、红外接收模块共地
- 控制接口位于 `camera_tilt.h`：`CameraTilt_SetLevel()`、`CameraTilt_SetDown()`、
  `CameraTilt_SetPulseUs()`

## 光电传感器预留

- 传感器1：`PB11 / EXTI11`
- 传感器2：`PB12 / EXTI12`
- 传感器3：`PD8 / EXTI8`
- 三路均为上拉输入、上升沿和下降沿中断
- `PhotoSensor_GetState()`返回GPIO原始电平；各传感器的遮挡极性按实测配置
- `PB13/PB14` 没有用于传感器中断，因为 EXTI13/14 已分配给
  `PD13/PD14` 的底盘编码器
- 三路均记录实时电平和变化标志；传感器2、3暂不执行运动控制
- 传感器1（`PB11`）实测为无遮挡低电平、遮挡高电平，作为X/Z两轴共用方向限位
- 任一轴运动时触发PB11，最迟在10ms控制周期内记录触发轴和方向并停止该轴
- 遮挡期间仅允许触发轴沿相反方向脱离，原方向和另一轴均禁止启动
- 光束恢复后自动解除方向限位；上电时已经遮挡且没有触发记录时，两轴均禁止启动
- Z轴正常停止或触发光电门时仅关闭PUL脉冲，TB6600的ENA保持低电平以提供静态保持转矩
- X轴正常停止仍释放驱动；系统初始化、急停和安全故障调用`StepperAxis_StopAll()`时两轴均彻底释放
- Z轴保持会持续产生线圈电流和热量，应根据负载调整TB6600电流档位并检查电机温升
- `StepperAxis_MovePulses(axis, pulse_count, reverse)`可非阻塞输出指定数量的步进脉冲
- TIM1捕获比较中断在每个完整脉冲下降沿计数，达到目标后自动停止；X轴释放、Z轴进入保持
- 可通过`StepperAxis_GetCommandedPulses()`、`GetCompletedPulses()`和`GetRemainingPulses()`记录标定数据
- 指定脉冲运动中若触发光电门或安全停机，本次运动会被取消，已完成计数保留供诊断

### 步进轴实机标定（2026-07-26）

| 轴 | 实测基准 | 脉冲数 | 换算结果 | 建议安全工作行程 |
| --- | --- | ---: | ---: | ---: |
| X轴 | 两端光电门之间约169.3cm | 33924 | 约200.38脉冲/cm，0.04991mm/脉冲 | 33424脉冲，预留500脉冲约2.50cm |
| Z轴 | 夹爪触底遮挡光电门至向上最大28.1cm | 5784 | 约205.84脉冲/cm，0.04858mm/脉冲 | 5584脉冲，上端预留200脉冲约0.97cm |

- `app_config.h`集中保存上述标定值，路线规划优先使用安全工作行程，不要直接使用机械全行程。
- 单次`StepperAxis_MovePulses()`指令不得超过对应轴的实测完整行程，超出时返回`HAL_ERROR`且不会启动。
- 当前脉冲累计值是软件输出计数，上电后不是可信绝对坐标；后续必须增加X/Z回零流程，在光电门确认原点后才能启用绝对位置软限位。
- X轴两端光电门和Z轴触底光电门继续承担硬限位。调试新路线时应先低速、短距离运行，再逐步扩大行程。
- Z轴停止后保持使能以防夹爪下滑；长期保持时检查步进电机和TB6600温升，急停时仍会释放两轴驱动。

## K230视觉通信协议

- STM32 USART2：`PA2 TX`、`PA3 RX`，`115200 8N1`，RX/TX均使用DMA
- K230 UART1：`IO40 TX`、`IO41 RX`，与STM32交叉连接并共地
- STM32默认每200ms发送一次单次识别请求，不在中断中解析协议
- DMA回调只把数据写入512字节环形缓冲；`K230_RX`任务负责组帧、CRC和结果发布
- 帧格式：`AA 55 | 版本 | 命令 | 序号LE16 | 负载长度LE16 | 负载 | CRC16/MODBUS`
- 请求命令：`0x10`单次、`0x11`开始流、`0x12`停止流、`0x20`切换任务
- 响应命令：`0x90`识别结果、`0xA0`任务切换确认；切换任务负载为1字节任务ID
- 结果负载：任务类型、目标数量，以及每个目标的语义、置信度、中心X和中心Y
- 最多保存16个目标；数字语义为`1~5`，豆子语义为`0x11/0x12/0x13`
- `K230Link_GetLatestResult()`提供一致的完整快照，供后续路线规划读取
- 超过1.2秒没有合法结果帧时，系统将视觉状态标记为离线
- OLED视觉页按K230返回的640像素横坐标实时显示目标位置：数字模式使用5个固定位置框，豆子模式使用3个固定位置框；同一区域出现多个目标时显示置信度最高的目标
- 视觉页按遥控器`1`选择数字识别、按`2`选择豆子识别；方向键和电源键不控制机构
- 模型切换期间暂停识别请求，收到K230的ACK后清除旧结果并恢复5Hz单次请求
